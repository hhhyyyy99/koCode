# AI 通用工作规范

本文件适用于所有修改。开始任何任务前先读它，再按 `CLAUDE.md` 的路由读取更具体的规则。

## 工作顺序

1. 先看相关代码和现有测试，不凭记忆改。
2. 明确成功条件：修 bug 要能复现和验证；加功能要知道验收行为。
3. 改动保持小而直接，只触碰完成任务必须触碰的文件。
4. 优先沿用项目已有模式，不为单次需求新增抽象。
5. 完成后运行与风险匹配的验证命令。
6. 汇报时说明改了什么、验证了什么、还有什么风险。

## 回复语言

- 默认所有面向用户的回复必须使用中文。
- 只有在用户明确要求英文、需要保留代码/命令/错误原文、或引用上游英文内容时，才使用英文原文。

## 改动边界

- 不做用户没要求的顺手重构。
- 不格式化无关文件。
- 不删除或覆盖用户已有改动。
- 发现无关问题可以记录或告知，不直接修，除非它阻塞当前任务。
- 生成文件和源码要保持一致；如果源码变更影响 `packages/ko-cli/bin/kocode.mjs`，运行 `pnpm bundle`。

## 何时询问

遇到以下情况先问：

- 需求有多个合理解释，并且选择会影响架构或用户行为。
- 需要删除用户数据、重写历史、迁移配置或改变默认安全策略。
- 现有 OpenSpec 和用户请求冲突。
- 工作区已有无关修改阻塞当前任务。

其他情况下，做保守假设并继续推进。

## 代码风格

- TypeScript ESM，遵守现有 strict 类型风格。
- 避免 `any`，除非周边代码已有不可避免的外部边界。
- 优先使用结构化 API，不用脆弱字符串拼接处理结构数据。
- 注释只解释不明显的决策或复杂逻辑。
- 错误处理要服务真实场景，不为不可能状态堆代码。

## 安全默认值

- 工具执行、文件写入、bash 命令必须尊重权限系统。
- 测试和开发命令不要污染真实 `~/.kocode`，使用临时目录或 `KOCODE_SESSIONS_DIR`。
- 对路径处理保持 sandbox 思维：不要引入路径穿越风险。
